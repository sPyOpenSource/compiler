jll and jln Formats

Understanding the persistent representation of compiled jcore code and its linkage information.

Overview

In the jcore compiler, the compilation process produces two primary output files for each domain/library: the .jll file and the .jln file. These files are essential for the Ahead-of-Time (AOT) model, allowing the runtime to load and link native code without re-compiling.

  • .jll (Java Library Linkable): Contains the actual native machine code and detailed metadata about the classes and methods.
  • .jln (Java Linker Notification): Contains the resolved VTable (virtual method table) information, which the linker uses to resolve method calls at load time.

The .jll Format

The .jll file is a binary representation of the compiled domain. Its structure is defined in CodeFile.java.

High-Level Structure

FILE ::= HEADER code

The Header

The header contains the metadata necessary to understand the layout of the following code section.

Field Type Description
FORMATVERSION int Currently 10.
PROCESSOR string The target architecture (e.g., "x86", "x86profile").
NUMBER_OF_LIBS int Number of dependent libraries.
LIB* string Names of the required libraries.
METAINFO bytes Domain metadata (size followed by key-value pairs).
STRINGTABLE - A table of all strings used in the file to reduce redundancy.
NUMBER_OF_CLASSES int The number of classes defined in this domain.
CLASSHEADER* - Metadata for each class (see below).

Class Header Detail

Each class is described by a header that defines its memory layout and methods:

  • Class Metadata: Name, Superclass name, and Interface status.
  • Interface List: List of implemented interfaces.
  • Memory Layout:
    • Instance size and field map.
    • Static fields size and field map.
  • Method Table: A description of all methods in the class.
  • Method Headers: For each method:
    • Name and signature.
    • Local variable size and code size.
    • Argument map, return type, and flags.
    • Symbol table and line number mapping (for debugging).

The Code Section

Following the header is the raw native machine code for every method, ordered according to the class and method headers.

The .jln Format

The .jln file is a simplified "linker map" that records the final resolved positions of methods in the VTable. Its structure is defined in Main.java (in the vtable package).

Structure

  1. Magic Number: 0xaddedade (used to verify file type).
  2. Number of Classes: The count of classes in the domain.
  3. Class Entries: For each class:
    • className (string)
    • superClassName (string)
    • isInterface (int: 0 or 1)
    • Method Table:
      • type (int: 1 for class)
      • table_length (int)
      • Entries: For each slot in the VTable:
        • implemented_in_className (string)
        • methodName (string)
        • methodType (string)
        • ifMethodIndex (int)

Summary: The Relationship

When the runtime loads a domain, it reads the .jln file to quickly build the virtual method tables for all classes. This tells the system which piece of code to execute for a given method call. It then uses the .jll file to locate and load the actual native bytes of that code into memory.
